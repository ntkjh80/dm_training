# 13. 완료 확인과 다음 계획

## 오늘의 완료 확인

1. choice, noul, score를 자기 업무의 질문으로 한 개씩 설명할 수 있다.
2. 내 PC가 CUDA, MLX, CPU, 다른 GPU 중 어떤 경로인지 구분했다.
3. Laya로 한국어 문장을 실행해 실제 응답을 확인했다.
4. 학습 자료의 questions와 gold가 일치하며 중복 점검을 통과했다.
5. 학습을 수행했다면 저장 폴더와 지표 파일을 확보하고 새 프로세스에서 모델을 다시 불러왔다.
6. 가상 예제의 점수를 실무 성능으로 발표하지 않고, 별도 실제 시험 계획을 세웠다.

## 내 업무로 바꾸는 과제

업무 하나만 고르세요. 예를 들어 사내 문의의 담당 부서 배정이나 문서의 분류 태그입니다. 입력 한 건의 단위, 선택지, 모호한 경우 처리 기준을 먼저 정합니다. 정답을 합의한 자료를 모은 뒤 고객이나 문서 묶음이 섞이지 않도록 나누고, 기본 모델과 추가 학습 모델을 같은 시험 자료로 비교합니다.

성능 목표는 실제 비용과 연결합니다. 중요한 요청의 누락을 줄이는 것이 목표라면 재현율을, 검토 인력을 줄이는 것이 목표라면 자동 처리된 건의 정확도와 처리 비율을 함께 평가합니다. 분류가 이미 단순한 규칙으로 충분한지도 비교해 보세요.

## 배포 전 모델이 답해야 할 예제

| 사례 | 점검하는 능력 |
| --- | --- |
| 환불을 원하지 않는다고 명시한 문장 | 부정 표현과 진짜 요청 구별 |
| 새 상품명이나 처음 보는 고객 표현 | 학습 문장 외의 일반화 |
| 선택지 어디에도 잘 맞지 않는 문의 | other 또는 사람 검토 처리 |
| 길어진 문서의 마지막에 있는 핵심 요청 | 입력 길이와 잘림의 영향 |
| API 연결 실패나 불완전한 응답 | 실패를 정상 결과와 분리 |

## 검증 범위

동봉 자료는 공식 문서와 공개 구현의 인터페이스를 확인해 작성했습니다. 데이터 형식과 코드의 정적 점검은 수행했으며, 실제 GPU 학습과 모든 운영체제에서의 설치·추론은 이 자료 제작 과정에서 수행하지 않았습니다. 교육 예제와 실제 실행 결과를 구분하여 사용하세요.
