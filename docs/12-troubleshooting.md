# 12. 오류 해결과 성능 개선

| 증상 | 먼저 확인할 것 | 다음 조치 |
| --- | --- | --- |
| Decision model 항목이 없음 | 앱 버전과 기반 모델 종류 | 최신 공식 배포로 업데이트 |
| FastDecisionModel import 실패 | 다른 Python 환경을 사용했는가 | 실행 Python과 패키지 위치 확인 |
| MLX 관련 import 실패 | Apple Silicon과 최신 zoo 모듈 | 공식 설치기 재실행 또는 패키지 안내 적용 |

## 정확도가 좋아 보일 때도 확인할 것

우리 예제의 환불 정답은 대부분 false입니다. 시험 12건 중 true는 1건뿐이므로 항상 false만 말해도 이 질문의 정확도는 약 91.7%입니다. 그런데 환불 요청을 찾는 재현율은 0%입니다. 전체 정확도만 보고 모델이 좋아졌다고 말할 수 없는 이유입니다.

업무 자료로 확장할 때는 클래스별 개수와 혼동행렬, 중요한 클래스의 누락을 확인합니다. 원문 길이, 오탈자, 부정문, 두 가지 요청이 섞인 문장, 새로운 상품명처럼 실패 원인을 나누어 자료를 추가합니다. 마지막 시험 자료를 보고 계속 수정했다면 새 시험 자료가 필요합니다.

## 실무 적용 직전에 남길 기록

기반 모델과 리비전, 학습 데이터 버전, 질문과 선택지 정의, 실행 환경, 학습 설정, 보정 데이터, 최종 시험 결과, 처리 기준을 함께 보관합니다. 자동 처리 대상의 정확도와 사람에게 보내는 비율을 같이 보고, API 실패와 입력 잘림도 별도 집계합니다.

한국어 자료로 직접 확인하고, 설명이 필요하면 별도의 설명 생성 절차를 설계합니다. 판정 모델이 반환한 확률만으로 근거 문장이 자동으로 생기지는 않습니다.
