# Decision 모델 교육 진행 대본

60분 개념과 시연 수업 및 선택 실습 30분

기준일: 2026-10-11 · 초보자와 실습 진행자를 위한 한국어 자료

대상은 언어 모델을 사용해 본 적은 있지만 직접 학습하지 않은 학습자입니다. 수업이 끝나면 Decision 모델의 입력과 출력을 설명하고, 자기 PC에 맞는 경로를 선택하며, 내 업무용 학습 데이터 한 건을 작성할 수 있어야 합니다.

이 대본의 말하기 부분은 진행자가 그대로 읽을 수 있도록 작성했습니다. 활동과 시연을 포함한 60분 수업입니다. 학습 완료까지 걸리는 시간은 별도이므로 수업 전에 모델 다운로드와 데모 준비를 마칩니다.

| 시간 | 내용 | 화면 또는 활동 |
| --- | --- | --- |
| 0~6분 | 왜 Decision 모델인가 | 문의 한 문장으로 판단 나누기 |
| 6~14분 | 세 가지 질문과 구조 | 팀 배정과 환불과 긴급도 |
| 14~22분 | 확률과 평가 | 0.8의 의미와 검토 기준 |
| 22~29분 | 내 PC 경로 | PC 유형별 경로 고르기 |
| 29~38분 | 학습 전 체험 | Laya와 부정문 시연 |
| 38~49분 | 데이터와 학습 | JSONL 확인과 짧은 실행 |
| 49~56분 | 저장과 평가 | 실행 기록과 지표 읽기 |
| 56~60분 | 이해 확인 | 세 질문과 과제 제시 |

## 진행자 사전 준비

Unsloth를 설치하고 Laya 다운로드를 완료합니다. 학습 시연 PC의 기반 모델도 미리 받습니다. API 키를 화면에 노출하지 않도록 준비하고, 실습 데이터 48건이 가상 자료임을 소개합니다. 실제로 학습했다면 그 PC의 실행 시간과 지표를 저장해 두세요. 실행하지 않았다면 가상의 학습 성공 화면이나 수치를 만들지 않습니다.

현장 인터넷이나 GPU가 준비되지 않으면 데이터 작성과 API 요청 구조까지 진행합니다. 학습 결과 부분은 “학습 후 확인할 파일”로 설명하고, 실행 성공을 시연한 것처럼 말하지 않습니다.

## 학습자에게 미리 전달할 것

교재와 practice 폴더를 배포합니다. Windows, Apple Silicon Mac, Intel Mac, NVIDIA 또는 다른 GPU 여부를 알아오게 합니다. 설치를 수업 안에서 처음 시작하면 학습 활동 시간이 줄어듭니다. 수업 중에는 실제 고객 문서 대신 제공된 예제를 사용합니다.

## 0분부터 14분 개념 설명

### 0분부터 6분 말하기

“오늘은 고객 문의를 읽고 담당 팀을 고르는 작은 AI를 만들어 보겠습니다. 고객이 ‘중복 결제된 금액을 오늘 돌려주세요’라고 썼습니다. 여러분이 상담 담당자라면 먼저 무엇을 확인하시겠어요? 담당 팀은 어디인지, 환불 요청인지, 얼마나 급한지로 나눌 수 있겠죠. 우리가 프로그램에 넣고 싶은 것도 바로 이 세 가지 답입니다.”

“Decision 모델에는 원문만 보내는 것이 아니라 질문과 선택지도 함께 보냅니다. 예를 들어 담당 팀 후보가 결제, 기술지원, 영업, 기타라면 각 후보의 확률이 나옵니다. 이 결과를 보고 프로그램이 담당 팀 후보를 표시할 수 있습니다. 실제 돈을 환불하는 동작은 별도의 업무 절차입니다.”

**화면: 교재 [2장](02-decision-model.md)의 비교표. 활동: 학습자에게 자신의 업무에서 반복해서 고르는 값 하나를 적게 합니다. 1분 작성 후 두 사람의 예를 듣습니다.**

“방금 적은 분류가 명확한 고정 규칙으로 해결된다면 규칙부터 써도 좋습니다. 문장 표현이 다양하고 문맥을 읽어야 한다면 모델을 비교할 이유가 생깁니다. 먼저 해결할 판단을 작게 정하는 것이 오늘의 시작입니다.”

### 6분부터 14분 말하기

“질문은 세 가지 형태로 만들겠습니다. choice는 여러 후보 중 하나를 고릅니다. noul은 예 또는 아니오를 묻습니다. score는 낮음, 보통, 높음처럼 순서가 있는 단계를 고릅니다. 우리 예제에서는 담당 팀이 choice, 환불 요청 여부가 noul, 긴급도가 score입니다.”

“긴급도는 0, 1, 2로 정합니다. 여기서 숫자는 우리가 만든 기준입니다. 0은 급하지 않다고 명시한 경우, 1은 보통 문의, 2는 오늘 처리 요청이나 현재 업무 중단입니다. 목소리가 크거나 느낌표가 많다고 무조건 2로 정하지 않습니다. 사람이 같은 기준으로 정답을 붙일 수 있어야 학습할 수 있습니다.”

“모델 안에서는 언어 모델이 문맥을 읽고 작은 Decision head가 선택지별 점수를 만듭니다. LoRA는 큰 모델의 모든 가중치를 다시 바꾸는 부담을 줄이는 방법입니다. 작은 추가 가중치와 판정 모듈을 학습한다고 생각하면 됩니다. 여기서 4비트는 메모리를 줄이는 설정입니다. 학습 전체가 모델 파일 크기만큼의 메모리만 쓴다는 뜻은 아닙니다.”

**활동 2분: “환불 규정이 궁금하지만 취소할 생각은 없습니다”에 대해 담당 팀과 환불 여부를 적게 합니다. 기대 답은 billing과 false입니다. 긴급도는 시점 언급이 없으므로 1입니다.**

“세 가지 판단의 답이 서로 다를 수 있다는 점을 확인했습니다. 결제 팀이 맡아도 환불 요청은 아닐 수 있습니다. 이런 구분을 questions와 gold에 명확히 담겠습니다.”

## 14분부터 29분 확률과 PC 환경

### 14분부터 22분 말하기

“화면의 확률이 0.8이라면 어떻게 읽어야 할까요? 이 문장이 반드시 맞는다는 보장은 아닙니다. 비슷한 확률을 낸 판단을 여러 개 모았을 때 실제로 얼마나 맞는지 확인해야 합니다. 0.8이라고 말한 100건 중 약 80건이 맞으면 그 구간의 확신이 실제 결과와 잘 맞는다고 볼 수 있습니다.”

“모델은 잘못된 답을 자신 있게 고를 수도 있습니다. 그래서 정확도와 확률 보정을 따로 봅니다. 학습 자료로 모델을 조정하고, 별도 보정 자료로 확신의 크기를 조절하며, 최종 시험 자료로 결과를 확인합니다. 시험 자료를 보고 계속 바꾸면 더 이상 새로운 문제를 푸는 시험이 되지 않습니다.”

**화면: 가상의 팀 확률 billing 0.82, technical 0.10, sales 0.05, other 0.03. 이 숫자가 실측이 아닌 설명용임을 표시합니다.**

“이 확률이면 billing을 가장 유력한 팀으로 봅니다. 연습에서는 0.8 이상일 때 후보로 표시하고 그 아래면 사람이 확인하도록 하겠습니다. 0.8은 업무에서 검증된 정답이 아닙니다. 처리량을 늘릴 때 오류가 얼마나 늘어나는지 보고 기준을 정해야 합니다.”

**활동 2분: 환불 여부 확률이 0.03인 경우 “불확실함”인지 “아니오 쪽으로 강함”인지 선택하게 합니다. 설명: noul의 값이 예의 확률이라면 아니오 쪽이 강합니다. 단, 보정 상태는 별도로 확인합니다.**

“API의 confidence라는 필드는 선택지 확률과 다를 수 있습니다. 우리 코드는 probabilities의 실제 후보 값을 읽습니다. 이름이 비슷해도 숫자를 같은 방식으로 해석하지 않는 것이 중요합니다.”

### 22분부터 29분 말하기

“이제 PC를 고르겠습니다. 이미 학습된 Laya를 실행하는 체험은 CPU에서도 시작할 수 있습니다. 반면 내 데이터로 모델을 학습하려면 그 학습 경로를 지원하는 환경이 필요합니다. Windows와 Linux의 NVIDIA GPU는 CUDA 경로를, Apple Silicon Mac은 최신 MLX 경로를 확인합니다.”

“Mac에서 학습이 전혀 안 된다는 설명은 현재 구현과 맞지 않습니다. Apple Silicon용 Decision 학습 코드가 있습니다. 다만 Intel Mac이나 GPU 없는 PC는 오늘의 입문 경로로 Colab을 권합니다. AMD와 Intel GPU에도 설치 안내가 있지만, 자신의 모델과 드라이버 조합을 작은 실행으로 확인해야 합니다.”

**활동 2분: 교재 [5장](05-pc-environments.md)의 표에서 자기 PC에 맞는 줄을 고르게 합니다. RAM과 GPU 전용 메모리를 혼동하는 사람이 있는지 확인합니다.**

“원문에 10분이라고 쓰인 예가 있어도 내 PC에서 10분이라는 뜻은 아닙니다. GPU, 모델, 데이터 길이에 따라 시간이 달라집니다. 오늘은 작동을 짧게 확인하고 전체 학습은 준비한 환경에서 이어가겠습니다.”

## 29분부터 38분 로컬 모델 시연

### 화면 조작과 말하기

1. Unsloth의 Settings → API → Decision API를 엽니다. 키가 보이는 영역은 화면 공유에서 가립니다.
2. Serve requests가 켜져 있는지 확인하고 multilingual 모델을 선택합니다.
3. Try It에 동봉 request.json의 state와 questions를 입력합니다. UI 입력란 구성은 설치 버전에 맞춥니다.
4. 첫 문장과 부정문을 차례로 실행하고 실제 응답을 함께 읽습니다.

“지금 사용하는 모델은 이미 학습되어 있는 Laya입니다. 아직 여러분의 자료로 가중치를 바꾸지 않았습니다. 먼저 질문을 작성하고 응답을 읽는 흐름을 익히겠습니다. 원문은 state, 판단 기준은 questions에 들어갑니다.”

“처음 요청은 모델을 메모리에 올리느라 느릴 수 있습니다. 두 번째 요청과 시간을 따로 보겠습니다. 이 화면에 실제로 나온 숫자를 기록하세요. 교재에 나온 설명용 확률과 같을 필요는 없습니다.”

“다음 문장을 ‘환불은 원하지 않습니다. 규정만 알려주세요’로 바꾸겠습니다. 단어 환불이 들어 있어도 고객이 돈을 돌려달라는 요청은 아니죠. 이 구분을 모델이 하는지 보겠습니다. 틀렸다면 숨기지 않고 어떤 표현에서 틀렸는지 적어 둡니다.”

### 학습자 활동 3분

각자 문장 하나를 새로 만듭니다. 정답도 먼저 적습니다. 예를 들어 “다음 달 도입할 상품 견적이 필요하고 급하지 않습니다”는 sales, false, 0이 됩니다. 서로 문장을 교환해 사람이 고른 답과 모델의 답을 비교합니다.

### API로 연결하는 시연

“화면 체험이 끝나면 같은 요청을 프로그램에서도 보낼 수 있습니다. practice 폴더에서 call_api.py를 실행하겠습니다. 이 코드는 우리 PC의 API에 요청하고 JSON 응답을 출력합니다. 모델이 어떤 답을 했는지와 프로그램이 그 답으로 무엇을 할지는 별도입니다.”

```bash
python call_api.py
```

**진행자는 실제 선택지 확률이 있는지 확인합니다. 연결 실패 때 가짜 확률을 보여주지 않습니다. 포트와 Serve requests, API 토큰을 확인하고 시간이 오래 걸리면 요청 형식 설명으로 전환합니다.**

“이제 학습 전의 출발점을 얻었습니다. 이 모델이 충분히 잘 작동하면 그대로 평가를 진행할 수 있습니다. 우리만의 분류 기준이나 표현에서 실패한다면 정답 자료를 만들어 추가 학습을 비교하겠습니다.”

## 38분부터 49분 데이터와 학습

### 38분부터 44분 말하기

“학습 자료 한 줄을 열어 보겠습니다. state는 고객 문장이고 questions는 우리가 묻는 질문입니다. gold는 사람이 정한 답입니다. team의 정답은 billing처럼 선택지 키와 정확히 같아야 합니다. refund는 true 또는 false, urgency는 0부터 시작하는 정수입니다.”

“데이터를 읽을 수 있다는 것과 좋은 데이터라는 것은 다릅니다. 같은 문장이 학습과 시험에 같이 있으면 모델이 외운 것을 측정할 수 있습니다. 문장이 조금 달라도 같은 고객 대화에서 잘라 온 것이라면 묶어서 나누는 편이 좋습니다.”

“동봉 예제는 전체 48건입니다. 학습 24건, 보정 12건, 시험 12건으로 나눴습니다. 한 건마다 세 질문이 있으니 질문 개수는 세 배입니다. 문서 수와 판단 수를 구분해서 결과를 말하겠습니다. 이 정도 자료는 절차를 체험하기에는 좋지만 실무 성능을 말하기에는 너무 작습니다.”

**활동 3분: 질문 유형 하나를 선택해 JSON 정답 한 건을 작성합니다. 옆 사람은 선택지 키, 참거짓 타입, 단계 번호를 확인합니다. 잘못된 예로 "refund": "예"와 "urgency": 3을 제시하고 수정하게 합니다.**

### 44분부터 49분 학습 시연

“먼저 데이터 점검을 실행하겠습니다. 통과했다는 메시지는 형식과 일부 중복 검사에 대한 결과입니다. 문장의 정답이 맞다는 보증은 아닙니다.”

```bash
python train_decision.py --check-data
```

“화면으로 학습한다면 Train as를 Decision model로 바꿉니다. 일반 채팅 학습과 목표가 다릅니다. 작은 0.8B 모델, batch 1, 입력 길이 1024로 시작하겠습니다. rank 16과 학습률 2e-4는 비교할 시작값이지 모든 데이터의 최적값은 아닙니다.”

“코드로는 아래 명령을 사용합니다. 5 step은 모델 품질을 평가하는 실험이 아니라 메모리와 저장 흐름을 확인하는 짧은 점검입니다. 작동하면 별도의 실행에서 2 epochs를 체험합니다.”

```bash
python train_decision.py --max-steps 5 --output outputs/live
```

**진행자는 이미 outputs/live가 있다면 새 이름을 사용합니다. 모델 다운로드가 끝나지 않았거나 학습이 오래 걸리면 그대로 실행 상태를 설명하고 다음 설명을 진행합니다. 49분에 반드시 완료된다고 약속하지 않습니다.**

## 49분부터 60분 결과와 이해 확인

### 자주 받는 질문과 답변

질문: “한국어로 바로 학습하면 되나요?”
답변: “한국어 입력과 정답 자료를 만들 수 있습니다. 다만 공개 영어 벤치마크 수치가 한국어 정확도를 보장하지는 않습니다. 한국어 부정문과 업무 용어를 포함한 별도 시험을 준비하세요.”

질문: “Mac에서는 NVIDIA GPU가 없는데 어떻게 하나요?”
답변: “Apple Silicon에는 MLX 기반 Decision 학습 구현이 있습니다. 최신 앱과 패키지, 지원 모델을 확인하세요. Intel Mac은 이 경로와 다르므로 입문 학습은 Colab을 선택할 수 있습니다.”

질문: “내 PC에 모델을 만들려면 꼭 내 PC에서 학습해야 하나요?”
답변: “학습 장소와 실행 장소는 다를 수 있습니다. 다만 학습한 파일을 로컬로 옮긴 뒤 그 모델과 head를 지원하는 실행기가 필요합니다. CPU에서 가능한 Laya 체험과 GPU가 필요한 병합 모델 서빙은 구분하세요.”

질문: “정답 자료는 몇 건이면 충분한가요?”
답변: “업무와 선택지 수에 따라 다릅니다. 검토된 자료를 조금씩 늘리면서 새로운 시험 자료의 오류가 줄어드는지 확인합니다. 같은 문장을 반복해 행 수만 늘려서는 충분한 다양성이 생기지 않습니다.”

질문: “확률이 0.99이면 자동 처리해도 되나요?”
답변: “실제 업무 자료에서 그 구간의 오답률과 실패 비용을 확인해야 합니다. 확률 숫자만으로 기준을 정하지 말고, 자동 처리된 건의 정확도와 검토율을 같이 봅니다.”
